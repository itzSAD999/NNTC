# Security & compliance — NMTC Platform

Operational checklist before handling real student data.

## Supabase Auth (dashboard)

### MFA for privileged staff

In **Supabase → Authentication → Providers / MFA**, enable TOTP (and optionally phone) for staff.

Require MFA especially for:

- `super_admin` (break-glass)
- `principal` (final document approval)
- `accounts` (payment confirmation)

The app enforces **AAL2** (MFA completed this session) for workflow actions in **production** for those roles (`lib/auth/mfa.ts`). After enrolling MFA in Supabase, staff must sign out and sign in again with their second factor.

### Staff accounts are deliberate

Access requires **both**:

1. A row in `auth.users` (login credentials)
2. A matching row in `staff_accounts` with `is_active = true`

A bare Auth signup does **not** grant dashboard access. Staff rows are created only by Super Admin via **Users CMS** (`lib/actions/users.ts`). Do not add triggers or hooks that auto-provision `staff_accounts` on signup.

## App-layer responsibilities

| Concern | Implementation |
|--------|----------------|
| **Receipts private** | `requests.receipt_url` stores the object path within the `receipts` bucket (not a public URL). Staff view via `createSignedUrl` with **60s** TTL (`RECEIPT_SIGNED_URL_TTL_SECONDS`). |
| **Public submissions** | Request insert + receipt upload use **service role** server-side only (`lib/actions/requests.ts`, `lib/supabase/admin.ts`). Never expose `SUPABASE_SERVICE_ROLE_KEY` to the client. |
| **Spam / abuse** | Cloudflare **Turnstile** on contact, request submit, and track forms. Per-IP rate limits in `lib/security/rate-limit.ts`. Add Cloudflare/Vercel edge rules in production. |
| **Workflow transitions** | DB trigger `enforce_request_transition()` is authoritative. UI shows only legal next actions via `getWorkflowUiActions()` (`lib/requests/transitions.ts`). |
| **Reference numbers** | Generated by DB default `gen_reference_no()` — **do not** send `reference_no` from app code on insert. |

Apply DB hardening: `supabase db push` (migration `20250621000011_production_hardening.sql`).

## Storage buckets

| Bucket | Access | Use |
|--------|--------|-----|
| `receipts` | **Private** | Payment evidence. Signed URLs only. |
| `public-assets` | **Public** | Logos, covers, CMS images. Keys prefixed with `crypto.randomUUID()`. |
| `documents` | **Public** | Handbooks, forms, timetables (meant to be shared). Keys: `{category}/{uuid}-{filename}`. |

**Rule:** Never put confidential files in `public-assets` or `documents`. `is_published` controls listing, not URL guessability in public buckets.

## Ghana Data Protection Act, 2012 (Act 843)

The platform processes student PII (names, IDs, email, phone, payment evidence). **Before launch**, agree with the college:

1. **Retention** — How long completed/collected requests and receipts are kept; routine purge/archive after that window (schema retains indefinitely by default).
2. **Purpose & access** — Document role-based access (RLS already enforces least privilege).
3. **Registration** — Whether the college must register as a data controller with Ghana's Data Protection Commission.

This is a college governance decision, not a technical default.
